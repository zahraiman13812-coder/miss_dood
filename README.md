# MISS DOOD — PostgreSQL + pgAdmin (بدون Docker)

این نسخه با **Next.js 16 / Node.js 22 / PostgreSQL 15+** کار می‌کند. **pgAdmin فقط ابزار مدیریت دیتابیس است و خود PostgreSQL Server نیست**. مطمئن شوید سرویس PostgreSQL روی سیستم یا سرور اجرا می‌شود. در این بسته عمداً هیچ Dockerfile، docker-compose یا فایل Docker وجود ندارد.

## ۱. ساخت دیتابیس در pgAdmin

1. در pgAdmin به سرور PostgreSQL متصل شوید (رمز سرور را باید خودتان بدانید).
2. در Servers > PostgreSQL > Databases روی `Create > Database` کلیک کنید و نام را `missdood` بگذارید؛ Owner را همان کاربری انتخاب کنید که در URL اتصال می‌گذارید (معمولاً `postgres`).
3. روی دیتابیس `missdood` کلیک کنید و **Query Tool** را باز کنید.
4. فایل `db/001_init.sql` را در Query Tool باز کرده و Execute کنید (F5). این فایل اسکیمای جداول را می‌سازد، نه خود دیتابیس را.
5. در Schemas > public > Tables جداول `users`, `products`, `orders`, `order_items`, `shipping_rules` و بقیه را چک کنید.

**توجه:** اگر دیتابیس قبلاً داده دارد، پیش از هر تغییر Backup بگیرید. روی دیتابیس دیگری این SQL را ناخواسته اجرا نکنید.

## ۲. اتصال پروژه به PostgreSQL

Node.js **22 یا جدیدتر** نصب کنید. فایل `.env.example` را به `.env.local` کپی و اطلاعات سرور خود را ویرایش کنید:

```env
DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@127.0.0.1:5432/missdood
DATABASE_SSL=false
```

اگر PostgreSQL در سیستم دیگری است، به‌جای `127.0.0.1` آدرس سرور را وارد کنید و تنظیمات دسترسی شبکه، `pg_hba.conf` و فایروال را طبق سیاست امنیتی سرور انجام دهید. پورت 5432 را بدون محدودیت به اینترنت عمومی باز نکنید. اگر رمز شامل `@`، `#`، `/` یا `%` است، آن را **URL encode** کنید. هرگز `.env.local` را منتشر نکنید.

## ۳. نصب و اجرا (Windows PowerShell یا ترمینال)

در پوشه اصلی پروژه:

```bash
npm install
npm run db:check
npm run db:seed
npm run dev
```

سپس `http://localhost:3000` را باز کنید. `db:seed` تنها تعدادی محصول نمایشی با موجودی صفر اضافه می‌کند و داده محصولات موجود را overwrite نمی‌کند. **اگر قصد فروش دارید موجودی و تعرفه ارسال را از پنل مدیریت ثبت کنید.**

### ساخت مدیر

ابتدا در سایت با ایمیل خود ثبت‌نام کنید و سپس در **PowerShell** اجرا کنید:

```powershell
$env:ADMIN_EMAIL="you@example.com"
npm run admin:promote
Remove-Item Env:ADMIN_EMAIL
```

در لینوکس/macOS:

```bash
ADMIN_EMAIL=you@example.com npm run admin:promote
```

این دستور را فقط کسی که به خود سرور دسترسی دارد اجرا کند؛ مسیر عمومی ایجاد مدیر وجود ندارد.

## ۴. استقرار روی دامنه بدون Docker

برای سرور/VPS با Node.js 22 و PostgreSQL موجود:

```bash
npm install
npm run db:check
npm run build
npm run start
```

سایت به‌صورت پیش‌فرض روی پورت 3000 اجرا می‌شود. فایل `deploy/nginx.conf` یک نمونه reverse proxy است: دامنه نمونه را با دامنه واقعی جایگزین کنید، Nginx را پیکربندی کنید، DNS را به IP سرور اشاره دهید و با Certbot گواهی HTTPS فعال کنید. برای اجرای دائمی Node.js از systemd یا یک process manager استفاده کنید. برای نمونه سرویس `deploy/missdood.service.example` را متناسب با نام کاربری/مسیر پروژه تغییر دهید؛ **مقادیر داخل آن نمونه‌اند و بدون ویرایش قابل استفاده نیستند**. پورت سایت را ترجیحاً فقط روی localhost نگه دارید؛ PostgreSQL باید تنها برای برنامه قابل دسترس باشد.

**محدودیت هاست اشتراکی:** لازم است هاست قابلیت اجرای دائم Node.js و اتصال PostgreSQL داشته باشد؛ صرف داشتن pgAdmin کافی نیست.

## امکانات و وضعیت فعلی

- APIهای ثبت‌نام، ورود و خروج، کاتالوگ، سفارش، مدیریت کالا/موجودی و پیگیری سفارش روی PostgreSQL کار می‌کنند.
- تیکت و علاقه‌مندی‌های کاربران واردشده در PostgreSQL ذخیره می‌شوند.
- سفارش‌ها با محاسبه قیمت و موجودی سمت سرور و تراکنش دیتابیس انجام می‌شوند.
- پرداخت آنلاین طبق درخواست غیرفعال است؛ **روش دریافت وجه را قبل از فروش واقعی مشخص کنید**.
- `npm run db:cleanup` نشست‌های منقضی‌شده را پاک می‌کند (می‌توانید دوره‌ای اجرا کنید).
- فایل‌های قدیمی Supabase فقط برای سابقه باقی مانده‌اند و مسیر اجرای این نسخه نیستند.

## پشتیبان‌گیری

در pgAdmin روی دیتابیس `missdood` راست‌کلیک و **Backup** را انتخاب کنید. بازیابی را ابتدا روی دیتابیس آزمایشی امتحان کنید. بکاپ منظم و نگهداری نسخه خارج از سرور فروشگاه توصیه می‌شود.

## موارد ضروری پیش از انتشار عمومی

این نسخه در محیط واقعی شما Build و تست عملیاتی نشده است. قبل از انتشار عمومی به محدودسازی نرخ تلاش ورود و APIها، تأیید ایمیل و بازیابی رمز، CSRF/Origin review، بکاپ/بازگردانی، HTTPS، مانیتورینگ، آزمایش سفارش/لغو/بازگشت موجودی، و قوانین حریم خصوصی و فروش نیاز دارد.

## ساختار

- `db/001_init.sql` — SQL را در pgAdmin Query Tool اجرا کنید.
- `.env.example` — نمونه اتصال که باید به `.env.local` تبدیل شود.
- `scripts/check-db.mjs` — بررسی دسترسی و وجود جداول.
- `scripts/seed.mjs` — داده نمونه.
- `scripts/promote-admin.mjs` — دسترسی مدیر.
- `deploy/nginx.conf` — Reverse proxy بدون Docker.
- `deploy/missdood.service.example` — اجرای سرویس Node.js (نمونه).


## اصلاحات امنیتی و باگ‌ها (نسخه بازبینی‌شده)

- پروژه فقط از **PostgreSQL اختصاصی** و نشست HttpOnly استفاده می‌کند؛ وابستگی قدیمی Supabase حذف شده است.
- برای جلوگیری از ثبت سفارش تکراری، شناسه درخواست `Idempotency-Key` افزوده شده است.
- محدودیت ۱۰ درخواست ورود/ثبت‌نام در هر ۱۵ دقیقه برای هر ترکیب ایمیل و IP اعمال شده است. برای راه‌اندازی روی اینترنت، Nginx باید هدر `X-Real-IP` را از IP واقعی مراجعه‌کننده تنظیم کند (نمونه موجود در `deploy/nginx.conf`).
- اگر قبلاً `db/001_init.sql` را اجرا کرده‌اید، فایل **`db/002_safety.sql`** را در pgAdmin Query Tool اجرا کنید. اگر دیتابیس کاملاً جدید می‌سازید، فقط `db/001_init.sql` کافی است.
- برای بررسی فایل‌های کلیدی: `npm run test:static`. بررسی اجرایی کامل همچنان نیازمند `npm install`, دیتابیس PostgreSQL در حال اجرا و `npm run build` است.
- هرگز رمز PostgreSQL یا `.env.local` را در مخزن عمومی قرار ندهید. پرداخت آنلاین همچنان غیرفعال است.

## بهبودهای نسخه موبایل و تجربه خرید

- کاتالوگ تنها پس از دریافت داده معتبر از API نمایش داده می‌شود؛ در صورت قطع PostgreSQL خطا و امکان تلاش مجدد وجود دارد.
- فیلتر کالاهای موجود، مرتب‌سازی الفبایی، صفحه راهنمای خرید در `/help` و امکان خالی‌کردن سبد اضافه شده‌اند.
- Checkout در زمان بارگذاری یا خطای کاتالوگ از ثبت سفارش جلوگیری می‌کند.
- برای بررسی سریع منابع، علاوه بر `npm run test:static` دستور `npm run test:smoke` قابل اجرا است.
- برای موبایل، حداقل اندازه لمس کنترل‌ها، محدودسازی عرض محتوا، چیدمان واکنش‌گرا، ورودی تلفن و کاهش حرکت لحاظ شده‌اند. آزمایش بصری روی مرورگر واقعی هنوز ضروری است.
